# Política de Segurança

## Versões suportadas

Enquanto o projeto não possuir uma versão estável publicada, correções de
segurança serão aplicadas à branch `main`. Depois da primeira versão estável,
somente a versão mais recente receberá correções.

## Relatando uma vulnerabilidade

Não abra uma issue pública para vulnerabilidades ou suspeitas de exposição de
credenciais.

Use o botão **Report a vulnerability** na aba **Security** ou acesse o
[formulário privado de reporte](https://github.com/Araendy-Aratyba/tesa/security/advisories/new).

Inclua, quando possível:

- descrição e impacto esperado;
- passos mínimos para reprodução;
- versões ou commits afetados;
- prova de conceito sem dados sensíveis;
- sugestão de correção, se houver.

O mantenedor confirmará o recebimento assim que possível, investigará o relato
e coordenará a divulgação depois que uma correção estiver disponível. Evite a
divulgação pública antes dessa coordenação.

## Escopo

Relatos sobre dependências devem indicar por que a vulnerabilidade é explorável
no Tesa. Problemas na API de Dados Abertos da Câmara dos Deputados devem ser
comunicados ao órgão responsável, exceto quando o Tesa ampliar ou expuser o
impacto do problema.
